Diagnosis used for this release
- Supplied v1.7 VPhoneGaGa log reports active netId=100.
- Default interface is eth0.
- Original DNS servers are 180.250.245.142 and 180.250.245.133.
- iptables NAT remains unavailable.

- Crucially, the app proxy reports: backend 127.0.0.1:5454 UDP=FAIL TCP=OK.
- v1.7 therefore aborted before starting the root bridge.

v1.8 fix
- Root resolver mode no longer requires UDP/5454.
- TCP/5454 is the required backend health check.
- Native helper keeps UDP+TCP listeners on 127.0.0.1:53 for Android compatibility.
- UDP/53 queries are encapsulated using the standard 2-byte DNS-over-TCP length prefix and sent to 127.0.0.1:5454 over TCP.
- The TCP DNS response is unpacked and returned as a normal UDP response to the Android resolver.
- TCP/53 requests continue to relay to TCP/5454.
- This isolates the app-side Java UDP problem without changing Android's resolver-facing protocol.

- End-to-end mock test passed with a backend that exposed TCP only:

  * TCP client -> 127.0.0.1:53 -> native bridge -> TCP backend -> TCP response: PASS.
- Native READY output reports backend=tcp.
- Android XML files parse successfully.
- GitHub workflow remains web-upload-friendly and compiles ARM64/ARMv7 helper with NDK 26.3 before Gradle/R8.
